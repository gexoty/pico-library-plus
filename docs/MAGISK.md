# Magisk: системная версия Pico Library

Версия предназначена для совместимого Pico 4 с root и Magisk. Это не универсальный APK для любых Android-устройств. Package name — com.pvr.appmanager, launcher — прежний com.pvr.appmanager.AllAppActivity. Код и интерфейс общие со standalone-версией.

ZIP содержит module.prop, customize.sh, cache-tools.sh, uninstall.sh, штатный установщик Magisk и его лицензию; приложение находится строго в system/priv-app/AppManager/AppManager.apk. В том же каталоге есть пустой .replace; customize.sh также указывает REPLACE для этого каталога. Используется штатный Magic Mount. Физический /system и оригинальный input/original.apk не меняются. service.sh, Zygisk, signature spoofing и собственных SELinux-правил нет.

Установщик зафиксирован из Magisk v28.1; источник и хеш указаны в magisk/UPSTREAM.md. Описание механизма: https://topjohnwu.github.io/Magisk/guides.html . Установку выполняет пользователь через приложение Magisk, затем перезагружает Pico 4. Автоматической установки в проекте нет.

Важное ограничение: собственная debug-подпись отличается от PICO. Наличие priv-app не передаёт платформенный сертификат, прежний shared UID или защищённые разрешения. sharedUserId намеренно отсутствует. Android и конкретная Pico OS могут отвергнуть замену из-за подписи, уже сохранённого пакета/данных, правил привилегированных разрешений или обновления из /data/app. Корректный ZIP не гарантирует совместимость. Проверки подписей и политики безопасности отключать не следует. Root выбирается существующим интерфейсом приложения; автоматического перехода между Root, System и Shizuku после отказа нет.

Для возврата предпочтительно удалить Pico Library в Magisk и перезагрузить устройство: uninstall.sh инвалидирует только кеш разбора AppManager с проверенной резервной копией. При простом отключении модуля uninstall.sh не выполняется; может потребоваться отдельно сохранить и удалить только /data/system/package_cache/*/AppManager-<числовые flags>, затем перезагрузить. Не очищайте весь package_cache и не меняйте packages.xml. Systemless-наложение исчезнет, исходный системный APK снова будет доступен. Отдельно установленное обновление /data/app и сохранённые данные могут влиять на результат; удаление пользовательских данных требует отдельного решения. При невозможности загрузки используйте заранее подготовленный способ отключения модуля средствами Magisk/восстановления конкретного устройства. Не удаляйте исходный AppManager и не записывайте системный раздел.

На A8110 / PICO OS 5.13.7 21 октября 2026 подтверждена проблема старого PackageParser-кеша и проверено её устранение точечной очисткой с перезагрузкой: система зарегистрировала 1.0.0 / 201905100, отдельный UID 10144, Shizuku provider и LauncherSettingsActivity. Библиотека и Activity настроек запущены, новых crash-записей нет; визуальная проверка в линзах и полный функциональный тест не выполнялись. При смене UID Android сам восстанавливал каталоги данных; сохранение старых настроек не гарантируется. Отчёт: MAGISK-SETTINGS-DIAGNOSIS.md.

С версии 1.0.1 установщик точечно очищает этот кеш перед перезагрузкой. Только файлы с именем AppManager-<число> непосредственно внутри каталогов /data/system/package_cache/* подходят под обработку. Кеши других пакетов, symbolic links и похожие имена не затрагиваются. Сначала выполняются копирование и побайтовое сравнение; ошибка прерывает обработку без удаления соответствующего оригинала. Резервные копии находятся в /data/adb/picolibrary-backups/install-<дата>-<pid>/ и uninstall-<дата>-<pid>/ с закрытым доступом; они сохраняются после удаления модуля. Безопасную ручную чистку этих резервных копий выполняет владелец позднее.

Этот механизм не отключает проверку подписи, не переносит системный UID и не выдаёт разрешения. На других прошивках совместимость требует отдельной проверки. Установка нового ZIP 1.0.1 и проверка обратного перехода к оригиналу на шлеме в этом этапе не выполнялись.
