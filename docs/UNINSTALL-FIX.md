# Удаление приложений — исправление 1.0.2

## Причина исчезновения карточки без удаления

На PICO OS 5.13.7 / A8110 библиотека 1.0.1 (UID 10144) получала DELETE_PACKAGES, однако после попыток удалить com.pico4.settings и com.amurcanov.tgwsproxy оба пакета оставались установленными. В журнале SilentInstaller видны вызовы deletePackage.

REA и smali исходного APK подтвердили: SilentInstaller.deletePackage вызывает скрытый PackageManager.deletePackage(String, IPackageDeleteObserver, int) через reflection с null observer. Затем DialogHelper$uninstall$1 без проверки результата удаляет локальную запись Room и вызывает refreshAppList с искусственным PACKAGE_REMOVED. Поэтому вызов удаления может завершиться асинхронным отказом, а UI уже показывает успех. Конкретный код отказа старого вызова неизвестен: callback отсутствовал. Это не подтверждает нехватку DELETE_PACKAGES или отказ Root.

## Исправление

После существующего подтверждения установленный обычный APK направляется в штатное окно Android ACTION_DELETE с URI package:<имя>. Добавлено REQUEST_DELETE_PACKAGES для standalone. Скрытый API и старый оптимистичный coroutine-путь для этих APK не вызываются. После отмены или ошибки открытия системного окна карточка и локальная запись не удаляются.

После настоящего защищённого системного PACKAGE_REMOVED дополнительно проверяется отсутствие пакета для текущего пользователя; только затем очищается локальная метаинформация и обновляется список. При замене/обновлении пакета очистка не выполняется. При завершении процесса действуют штатные ресиверы приложения и повторное обнаружение установленных приложений. Не используется Root, Shizuku или скрытый переход между ними: выбранный пользователем вариант исправления — системное подтверждение удаления. Настройки force-stop и каталога Store не менялись.

Веб-ярлыки и карточки магазина сохраняют исходный путь обработки. Имена Activity и интерфейс каталога не менялись. Само приложение, известные критические пакеты и системные/обновлённые системные APK защищены от этого пути удаления; com.pico4.settings не блокируется по имени и подтверждён как сторонний пакет из /data/app.

## Разрешённая аппаратная проверка

Пользователь явно разрешил резервирование и удаление com.pico4.settings. Перед тестом сохранены package metadata, base.apk (10 999 365 байт; SHA256 36f8ecc1b0662d574d3564d7b3575e2cd08053b95548c0f86013cb9ee9867ed2), архив данных app-data.tar (4096 байт, 6 записей). Хеш APK сверён с устройством, tar успешно прочитан. Пакет остановлен перед копированием данных.

Через ACTION_DELETE открыта com.android.packageinstaller/.UninstallerActivity. UI-иерархия подтвердила диалог Settings / «Удалить приложение?»; подтверждена именно кнопка ОК на его виртуальном дисплее. После удаления pm path и pm list packages --user 0 не находят пакет. APK и данные сохранены в .local-evidence/uninstall-test-com.pico4.settings/; содержимое резервных копий не коммитится. Пакет оставлен удалённым, автоматическое восстановление не выполнялось. Другие пакеты не удалялись.

Этот тест подтверждает системный маршрут удаления на данном устройстве. Интеграция 1.0.2 в обновлённой библиотеке ещё не устанавливалась на шлем. Проверка отмены и полного UI-пути новой библиотеки требует отдельного аппаратного этапа; не выдаётся за выполненную. Изменённые пакеты модуля и системные разделы на устройстве не заменялись; README сохранён.
