# Вылет настроек системной сборки — диагностика 21 октября 2026

Выполнено только чтение через ADB и Root на A8110 / PICO OS 5.13.7. Приложения не устанавливались, кеши и данные не удалялись, модуль и политики безопасности не менялись, перезагрузка не выполнялась.

Наблюдаемый вылет: ActivityNotFoundException для com.pvr.appmanager/com.gexoty.picolibrary.LauncherSettingsActivity. Источник вызова — LauncherSettings.open, строка 22. Ошибка возникает до onCreate настроек, а не внутри их интерфейса.

Файл /system/priv-app/AppManager/AppManager.apk содержит новый APK 1.0.0 / 201905100 и объявленную LauncherSettingsActivity. Он содержит разрешения Shizuku и не содержит sharedUserId. SHA256: 055a080969a8602f6892a7c03a83700585a477e41c72e66c546d3ca4e2577905. Тот же SHA256 получен из /proc/1357/root/system/priv-app/AppManager/AppManager.apk: system_server видит тот же файл. Модуль picolibrary сообщает 1.0.0 / 201905100, .replace присутствует в каталоге APK.

Однако dumpsys package и packages.xml показывают старую регистрацию: 2.9.5 / 200905100, sharedUserId 1000 и старый состав providers. Новая Activity системе неизвестна. Получается смешанное состояние: исполняется изменённый код по прежнему системному пути, а компоненты разрешаются по прежнему манифесту.

Найден старый кеш /data/system/package_cache/abe42c0946f0d7b0f223e8aba2869a8b536b4d0a/AppManager-16 от 19 сентября 2026; в нём нет строк LauncherSettingsActivity и ShizukuProvider. Время изменения подмонтированного каталога /system/priv-app/AppManager — 27 марта 1970, хотя сам APK имеет актуальную дату. Это согласуется с использованием устаревшего кеша разбора: Android 10 PackageParser.isCacheUpToDate сравнивает mtime переданного packageFile с mtime кеша; для кластерного пакета передаётся каталог.

Источник Android 10: https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-10.0.0_r47/core/java/android/content/pm/PackageParser.java (isCacheUpToDate/getCachedResult/parsePackage).

Вывод: подтверждена непосредственная причина вылета — новая Activity отсутствует в зарегистрированной модели пакета при её наличии в APK. Устаревший кеш и время каталога объясняют расхождение. Это не исправляется переименованием Activity или перехватом исключения в UI.

Для проверки исправления потребуется отдельный этап изменения устройства: резервное сохранение и точечная инвалидизация именно кеша AppManager с последующим пересканированием при загрузке. В этой диагностике это не выполнялось. После свежего разбора возможны самостоятельные проблемы совместимости: собственный сертификат отличается от PICO, новый APK не запрашивает прежний shared UID 1000, а текущая регистрация его всё ещё содержит. Нельзя заранее обещать успешную регистрацию после удаления кеша, править packages.xml, отключать проверку подписей или делать вывод о корректном наследовании системных прав.

Сырые журналы, копия APK, кеш и сведения о mount/mtime сохранены локально в .local-evidence/magisk-settings-crash/ и исключены из Git. README и исходный APK не изменены.

После согласия владельца сохранены точные байты кеша и packages.xml на ПК; packages.xml только читался. Выполнена одна перезагрузка.

После загрузки Package Manager зарегистрировал 1.0.0 / 201905100 и ShizukuProvider. В журнале: shared user changed from android.uid.system to <nothing>; replacing with new. Новый UID 10144. Android самостоятельно восстанавливал каталоги данных; скрипты проекта не меняли владельцев, packages.xml или app data. Сохранность прежних настроек не проверялась. Проверки безопасности не отключались.

Главная Activity и затем LauncherSettingsActivity запущены через am start из Root для проверки неэкспортированного экрана. Настройки достигли resumed; процесс оставался жив, буфер crash после перезагрузки пуст. Новый UID вызвал штатный запрос Root от Magisk; автоматическое изменение Root grants не выполнялось.
